# BrewCMS Project Governance

## Overview

BrewCMS is an open-source, community-oriented content operating system. This document outlines the project governance model, roles, decision-making processes, and contribution standards.

## Project Roles

### Benevolent Dictator for Life (BDFL) / Project Lead
- **Victor Kuldeep** (@victorkuldeep)
- Responsible for strategic technical direction, architectural integrity, and final decision-making on breaking changes or roadmap prioritization.

### Maintainers / Core Team
- Maintainers have commit access to the repository.
- Review pull requests, triage issues, ensure architectural adherence, and participate in technical RFC discussions.

### Contributors
- Anyone who submits issues, pull requests, documentation updates, or participates in community discussions.

## Decision-Making Process

1. **Architectural Decisions**: Material architectural changes must follow the Architectural Decision Record (ADR) process (see `.artifacts/23-DECISION-INDEX.md`).
2. **Consensus-Seeking**: Maintainers aim for consensus on technical designs. If consensus cannot be reached, the Project Lead makes the final decision.
3. **Transparency**: Discussions and roadmap items are kept transparent in public repositories and RFC threads.
